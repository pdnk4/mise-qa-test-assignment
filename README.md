# Тестовое задание: Junior QA Engineer (Manual + API)

Репозиторий с решением тестового задания по тестированию формы онлайн-бронирования столика и сопутствующего API-эндпоинта студии MISE.

### Структура репозитория
* `test-cases.md` — чек-лист и 22 тест-кейса с результатами фактического прогона (позитивные, негативные, граничные значения, UI/UX).
* `bug-reports.md` — 8 подробных баг-репортов с шагами воспроизведения, приоритетами и обоснованием (6 по фронтенду, 2 по API).
* `MISE_Booking_API_Tests.postman_collection.json` — дополненная коллекция для Postman с автотестами (assertions) и проверкой статус-кодов.

---

### Подход к тест-дизайну
При декомпозиции требований выделил ключевые зоны риска:
1. **Граничные значения:**
   * Количество гостей: `0` (ниже нормы), `1` (нижняя граница), `12` (верхняя граница), `13` (выше нормы).
   * Длина имени: `1` символ, `2` символа (минимальная допустимая граница).
   * Диапазон дат: прошлая дата, сегодня, ровно `+90` дней, `+91` день.
2. **Классы эквивалентности и форматы:**
   * Телефон: корректные варианты с кодами `+7` и `8`, разные разделители (пробелы, дефисы, скобки), ввод номера без кода страны (10 цифр), нецифровые символы.
   * Имя: поддержка кириллицы, дефисов и пробелов, проверка запрета на цифры и спецсимволы.
3. **Логика интерфейса:**
   * Проверка всех слотов времени (с 12:00 до 22:00).
   * Состояние кнопки при отправке (`disabled` + лоадер).
   * Сброс формы и очистка данных при клике на «Забронировать ещё».

### Результаты тестирования

#### UI (Демо-страница)
* **Прогнано тест-кейсов:** 22.
* **Результат:** 15 Pass / 7 Fail.
* **Ключевые дефекты:** форма позволяет бронировать столики на прошедшие даты и на даты свыше 90 дней, отсутствует лимит на максимальное число гостей (> 12), в выпадающем списке потерян слот на 22:00, а кнопка повторного бронирования не сбрасывает данные предыдущего гостя.

#### API (`POST /api/booking`)
* **Базовые сценарии:** 1 Pass / 4 Fail.
* **Ключевые дефекты:**
  * Сервер не обрабатывает ошибки клиентской валидации и падает в `500 Internal Server Error` вместо аккуратного ответа `400 Bad Request` при невалидном телефоне, отсутствии обязательного поля `name` или при значении `guests: 0`.
  * Валидация даты на бэкенде отсутствует полностью: запрос с датой `"2020-01-01"` возвращает `200 OK`.
