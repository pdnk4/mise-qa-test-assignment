## BUG-01: Телефон из 10 цифр без кода страны (9991234567) принимается как валидный

**Severity:** High
**Priority:** Critical

**Связанные тест-кейсы:** TC-PHONE-03

**Шаги воспроизведения:**
1. Открыть форму бронирования
2. Заполнить поля: Имя = «Анна», Дата = завтра, Время = 14:00, Кол-во гостей = 2, Телефон = `9991234567`
3. Нажать «Забронировать»

**Ожидаемый результат:**
Поле «Телефон» подсвечивается как невалидное, под полем появляется ошибка «Введите номер в формате +7XXXXXXXXXX или 8XXXXXXXXXX», форма не отправляется.

**Фактический результат:**
Ошибка валидации не появляется, форма успешно отправляется, отображается экран подтверждения брони.

**Обоснование приоритета:**
Ресторан не сможет дозвониться до гостя и подтвердить бронь по номеру без кода страны — это напрямую влияет на ключевой бизнес-процесс подтверждения брони, хотя сама форма и приложение работают технически корректно.

**Окружение:** Windows / Chrome _[версия]_

## BUG-02: Отсутствует валидация имени (минимальная длина и допустимые символы)

**Severity:** Medium
**Priority:** High

**Связанные тест-кейсы:** TC-NAME-03, TC-NAME-04, TC-NAME-06

**Описание:**
Поле «Имя» согласно требованиям должно содержать минимум 2 символа и только буквы, пробелы, дефис. Фактически проверяется только то, что поле не пустое — принимается любое непустое значение, включая однобуквенные имена, имена с цифрами и строки без единой буквы.

**Шаги воспроизведения (сценарий A — имя короче минимума):**
1. Открыть форму бронирования
2. Заполнить поля: Имя = `А`, Телефон = `+79991234567`, Дата = завтра, Время = 14:00, Гости = 2
3. Нажать «Забронировать»

**Ожидаемый результат:** Поле «Имя» невалидно, ошибка о минимальной длине (2 символа), форма не отправляется.
**Фактический результат:** Ошибки нет, форма отправлена успешно.

**Шаги воспроизведения (сценарий B — цифры в имени):**
1. Открыть форму бронирования
2. Заполнить поля: Имя = `Анна2`, Телефон = `+79991234567`, Дата = завтра, Время = 14:00, Гости = 2
3. Нажать «Забронировать»

**Ожидаемый результат:** Поле «Имя» невалидно (цифры не допускаются), форма не отправляется.
**Фактический результат:** Ошибки нет, форма отправлена успешно.

**Шаги воспроизведения (сценарий C — только дефисы, без букв):**
1. Открыть форму бронирования
2. Заполнить поля: Имя = `--`, Телефон = `+79991234567`, Дата = завтра, Время = 14:00, Гости = 2
3. Нажать «Забронировать»

**Ожидаемый результат:** Поле «Имя» невалидно (должно содержать хотя бы одну букву), форма не отправляется.
**Фактический результат:** Ошибки нет, форма отправлена успешно.

**Окружение:** Windows / Chrome _[версия]_

## BUG-03: Отсутствует валидация диапазона даты бронирования

**Severity:** High
**Priority:** High

**Связанные тест-кейсы:** TC-DATE-03, TC-DATE-04

**Описание:**
Поле «Дата» должно принимать только даты в диапазоне от сегодняшнего дня до +90 дней включительно. Фактически проверяется только то, что поле заполнено — принимаются и прошедшие даты, и даты за пределами +90 дней.

**Шаги воспроизведения (сценарий A — дата в прошлом):**
1. Открыть форму бронирования
2. Заполнить поля: Имя = «Анна», Телефон = `+79991234567`, Дата = вчера, Время = 14:00, Гости = 2
3. Нажать «Забронировать»

**Ожидаемый результат:** Поле «Дата» невалидно, ошибка о недопустимой дате, форма не отправляется.
**Фактический результат:** Ошибки нет, форма отправлена успешно.

**Шаги воспроизведения (сценарий B — дата дальше +90 дней):**
1. Открыть форму бронирования
2. Заполнить поля: Имя = «Анна», Телефон = `+79991234567`, Дата = сегодня + 91 день, Время = 14:00, Гости = 2
3. Нажать «Забронировать»

**Ожидаемый результат:** Поле «Дата» невалидно, форма не отправляется.
**Фактический результат:** Ошибки нет, форма отправлена успешно.

**Окружение:** Windows / Chrome _[версия]_

## BUG-04: В выпадающем списке «Время» отсутствует слот 22:00

**Severity:** Low
**Priority:** Critical

**Связанные тест-кейсы:** TC-TIME-01

**Шаги воспроизведения:**
1. Открыть форму бронирования
2. Открыть выпадающий список «Время»

**Ожидаемый результат:**
В списке присутствуют все слоты с 12:00 по 22:00 включительно, с шагом 1 час (всего 11 слотов).

**Фактический результат:**
В списке доступны слоты только с 12:00 по 21:00 (10 слотов), слот 22:00 отсутствует.

**Обоснование приоритета:**
Хотя технически UI не ломается и не теряет данные (отсюда низкая severity), пропавший вечерний слот — это прямая ежедневная потеря потенциальных броней на самое популярное время, поэтому чинить стоит в приоритетном порядке.

**Окружение:** Windows / Chrome _[версия]_

## BUG-05: Форма не очищается после нажатия «Забронировать ещё»

**Severity:** Medium
**Priority:** High

**Связанные тест-кейсы:** TC-FLOW-03

**Шаги воспроизведения:**
1. Заполнить форму валидными данными и отправить («Забронировать»)
2. Дождаться экрана подтверждения
3. Нажать «Забронировать ещё»

**Ожидаемый результат:**
Форма возвращается пустой — все поля очищены, готовы к новому вводу.

**Фактический результат:**
Форма отображается, но все ранее введённые значения (имя, телефон, дата, время, кол-во гостей) остаются в полях.

**Обоснование приоритета:**
Риск того, что пользователь по невнимательности создаст повторную бронь со старыми/чужими данными вместо новых — влияет на корректность данных при повторном использовании формы, частый сценарий для постоянных гостей ресторана.

**Окружение:** Windows / Chrome _[версия]_
